# dsh-deep-reading — 深度讲解

把一本书**讲透**。讲解为主，不提问。**不是摘要器，不是问答机器人。**

它做的是阅读里确定性的那一半：把文件变成可寻址的文本、把理解沉淀成结构化档案、把每一条引文拿去和原文逐字核对。讲解由会话里你自己的模型完成——**本插件不调用任何模型**。

定位是**深度讲解者**：第一轮直接开讲这一章在回答什么问题，一节一节讲下去，讲完一节讲下一节，不停下来等回应。用户主动提问时正常回答；除此之外输出里不出现问句。这条不只是写在提示词里——档案里的提问句式会被拒收。

## 谁决定讲解的结构

这是这个插件最要紧的一条，也是它从 source-shaped 改成 model-shaped 的原因。

**忠实于作者的意思，不忠实于作者的呈现顺序。**

按原书顺序一路注解下去，讲解得再聪明，读者听到的也是（带他精读）。所以管线里插了一步 **Model**：

```
SOURCE → READ → MAP → MODEL → REDUCE → TEACH
                          │
              读完整章 → 这一章真正在解决什么
                       + 讲解顺序（原序 / 重排 + 理由）
```

Model 是唯一**读完整章**的一步，而且它**不看 Map 的结论**——用分块碎片拼出来的（整章在讲什么）必然是碎片形状的，那正是要修掉的东西。它产出两个东西，写进档案头部：

- `## 这一章真正在解决什么` —— 一段话，能当三句话读。回答（在解决什么），不是（讲了什么）。
- `### 讲解顺序` —— 原序还是重排，以及为什么。**选原序也要给理由**：（原序就好）而不给理由，等于没问过这个问题。

Reduce 不再是（把 point 聚合起来），而是**把 point 挂到这个骨架上**；第一节小标题的顺序按讲解顺序排，不必等于原书顺序（大节顺序不动，那是四类声音的隔离）。

允许压缩（读 100% 可以只讲 30%）、允许自造例子（必须标注是 AI 举的，且不许进粗体）。

## 它解决什么

不装插件读一本书，模型要么把原文一段段读进上下文（500 页的书不可能塞进去），要么直接概括（于是"讲透"退化成复述）。两者都不是深度讲解。

这个插件的立场是：**判断可以交给模型，事实不能**。

- 书怎么切、行号是多少、引用对不对、档案合不合规——确定性的，插件做，可复现。
- 这一章在解决什么、机制是什么、边界在哪、该怎么讲——判断性的，模型做，可追溯。

讲解的深度靠四步落地：**主张 → 证据 → 机制 → 边界**。其中（机制）是最容易跳过的一步，也是 Map 阶段被强制要求填的槽位（填不出来必须在 `missing` 里标出，不许硬编）。

## 与已有书本工具的分工（重要）

DSH 里可能已经装着别的书本插件——它们把书变成可寻址文本，有自己的章节边界和引用校验。两者读的是同一批书，边界必须说清楚，否则你会得到**两套互相不认的章节边界**：

| | 已有的书本工具 | dsh-deep-reading（本插件） |
|---|---|---|
| 目的 | 把一本书读透并交付（理解 → 教学 → EPUB/PDF） | 把书讲透，并沉淀可回源的讲解底稿 |
| 文本获取 | 自己的解析器，稳定的单元 id | **不自行解析**：txt/md 直接读，epub/pdf 只出提示词，优先让子代理用会话里已有的书本工具 |
| 工具名 | `book_open` / `book_toc` / `book_segment` … | `reading_open` / `reading_archive` / `reading_status`（刻意不占 `book_*`） |
| 引用校验 | 按单元 id 校验 | 落盘时对**每一条**粗体做去空白/去引号/忽略大小写的子串比对 |

两者可以共存：别的插件回答"书在哪里"，本插件回答"讲到哪、哪些引文站得住"。

**没有别的书本工具也能用。** txt/md 完全走插件自己的确定性解析；epub/pdf 交给子代理，它用 `read`（必要时 `read_document`）把文本取出来即可。之所以不在这个插件里再写一套 EPUB/ZIP 解析，就是不想为同一本书产生第二套章节边界——那样两份引用会指向不同的行。

## 安装

需要 Node `^22.19.0 || >=24.0.0`，以及一个能用的 DSH 安装（`dsh --version`）。

```powershell
# 1) 把插件放进 profile（把 <本目录> 换成你 clone 下来的路径）
dsh plugin --profile web add <本目录>
# 或者手工：在 ~/.dsh/profiles/web/package.json 里
#   dependencies 加： "dsh-deep-reading": "link:<本目录>"
#   dsh.profile.bundles 末尾加： "dsh-deep-reading"
# 然后在 ~/.dsh/profiles/web 下跑 pnpm install

# 2) 重启 dsh web
```

装完先跑装载自检——它**不启动 dsh**，而是按宿主的安装路径解析插件、过一遍 `Config` schema、跑 `apply()`，并真的调用一次工具。装载层的问题会在这里暴露，而不是在你读书读到一半的时候：

```powershell
npm install        # 装 peer 依赖，跑测试和自检需要
npm run load-check
```

**读者数据不写在插件目录里**：默认落在 `$DSH_HOME/deep-reading`（见下一节）。插件是以 `link:` 装进 profile 的，把数据写进源码目录会被一次 re-clone 抹掉。

## 数据布局

`dataRoot` 默认 `$DSH_HOME/deep-reading`（**不在插件目录内**：本包是以 `link:` 装进 profile 的，把读者数据写进源码目录会被一次 re-clone 抹掉）。

```
<dataRoot>/
├── profile.json                     ← 阅读档案：进度 + 读者标记 + 跨书笔记
└── books/<bookId>/
    ├── manifest.json                ← 章节、行范围、块、波次、建档状态（单一真相）
    ├── source.txt                   ← 正文原样落盘（引用校验的 ground truth）
    ├── map/<块>.<promptRev>.json    ← Map 精读缓存（重跑不重付）
    ├── models/<章节>.<promptRev>.json ← Model 缓存（整章只读一次，重跑不重付）
    ├── drafts/<章节>.md             ← Reduce 写出的档案草稿
    └── archives/<章节>.md           ← 校验通过后的档案（含插件写的第五节）
```

`bookId = sha256(切分规则版本 + 正文内容)`。同一份文件重复导入是幂等的；改过正文或改过切分规则都会得到新书，不会让旧引用悄悄指向别处。

## 四个动作

| 动作 | 谁做 | 说明 |
|---|---|---|
| `reading_open` | 插件（零模型） | 文件 → 章节 / 行范围 / 块 / 波次；返回骨架，**不返回正文** |
| `workflow`（宿主原生） | 模型发起，子代理执行 | 每章：按块精读（Map）→ 读完整章形成 mental model（Model）→ 按模型组织成档案草稿（Reduce） |
| `reading_archive` | 插件（零模型） | 校验草稿并落盘；拒收时给 violations 与修法 |
| `reading_status` | 插件（零模型） | 进度 / 覆盖度 / 两类缓存 / 读者标记 / 下一波的 workflow args |

### 一个刻意的数据流设计

```
Map 子代理     读自己的行范围 → 写 map/<块>.json（结构化返回同一份）
Model 子代理   读整章         → 写 models/<章节>.json（结构化返回同一份）
Reduce 子代理  读上面两者     → 写 drafts/<章节>.md，只回一个三行回执
主代理         调 reading_archive → 插件从磁盘读草稿校验并落盘
```

每一步交给下一步的是**路径**，不是正文。反过来做（Reduce 的正文经 workflow 返回值回到主代理、再作为工具参数发出去）会让整轮最长的那段文字在驻留上下文里存两遍——这是上一个同类插件实测出来的最大单项开销（助手侧约 45k vs 工具侧约 17k 驻留）。

Model 缓存是单独一层：它要读整章，是一次波里最贵的单次调用，重跑时不该重付。

## 硬规则（会被执行，不是建议）

1. **引文一律用粗体 `**…**`**，里面只能是原文的**逐字复制**。校验：去掉空白、引号、大小写差异后做子串匹配。
2. **粗体只用于引文，不用于强调**。需要强调时用句式。这条是被执行的：每个粗体都必须逐字命中原文，拿来强调的粗体一定通不过。
3. **粗体成对且同行**（`V_QUOTE_UNCLOSED` / `V_QUOTE_CROSSLINE`）；**小标题里不许有粗体**（`V_QUOTE_IN_HEADING`）；**旧的引号式标记已废弃**（`V_QUOTE_GLYPH_RESIDUE`）。
4. **必须有 `## 这一章真正在解决什么`**（整章 mental model，≥40 字，且不是章节摘要）与 **`### 讲解顺序`**（≥30 字，且要出现（原序）或（重排）之一）。
5. 第一节列了判断就必须有引文。
6. 第二节标题必须含（推断）——读者要知道这是你的推断还是作者的意思。
7. 每条推演必须有 依据 / 理由 / 限制 / 状态；状态取 待验证 / 可接受 / 存疑。边界写不出来就写（原文未给边界）。
8. **第一节的每个小标题后面都要有一段 `### AI 视角`**；整节至少一段。推不出增量就写（这一节我没有额外的补充），不要硬编。AI 视角与在全书中的位置两节里的粗体**同样参与校验，没有例外**。
9. **章末必须有 `### 在全书中的位置`**。
10. **正文里不出现提问句式**（`你/您 …？`、`…吗？`、`你觉得`）。引文里的问句保留——那是作者在问。这条是定位的执行点：这个插件不向读者提问。
11. 第三节属于读者。没有 `readerInput: true` 时必须是 `（待读者填写）`。
12. 术语、概念、节名用（ ），不要用粗体，也不要用旧标记。自造例子绝不许进粗体。
13. 最后一节由插件写（路径、覆盖度、state、revision 都是插件的事实）。
14. 一段不超过 4 句 —— 这一条只给提示，不阻塞落盘（风格度量不适合硬拒收）。

## 配置

见 `cordis.patch.yml`，全部可选。写错类型的键只警告并回退默认值，不会让 profile 起不来。
`maxCharsPerChunk` 与 `maxChunksPerWave` 决定波次大小 = 单次 workflow 调用的子代理数（参照实现里这是被强制约束的，失控的分块计划会顶穿单次调用时限）。

## 现在没做的（别当成有）

- **第 3 阶段：整书地图 + 留白清单**（Reduce 跨章合成）——未实现。
- **第 4 阶段：自然涌现的跨书连接**——未实现。`profile.json` 里留了 `crossBookNotes` 字段，但**不主动建跨书索引**：两本无关的书被硬扯在一起，比不连接更糟。
- **上下文管理层**——未实现。这里有一个必须说清楚的更正：`dsh-clear-tool-results`（原本打算借鉴的对象）**已被作者弃用归档**，因为在 DeepSeek 真实峰价下（命中价是未命中的 1/50）按轮清除**不省钱**——清除会在上一轮首个工具结果处打断前缀缓存，之后全部全价重算；每步思维链 ≥1312 token 时收益归零，2000 时是 −8.3%。它仍然成立的价值是**上下文头寸**（峰值 198k → 111k，−44%），所以这一层应当按"买的是跑得完，不是省钱"来定位，并且占位符必须字节级固定。等做到这一层再定默认开关。
- **整章讲解正文不由插件产出**：插件产出的是**讲解底稿**（章节档案），讲解由会话里的模型照四步讲法讲出来。这是有意的分工——插件不调用任何模型。
- `epub` / `pdf` 的取文本路径只有提示词，**没有端到端验证过**。

## 开发

```powershell
npm test              # 52 个单元测试（结构/分块/校验/workflow），全离线
npm run load-check    # 装载自检：19 项
npm run drive         # 最小闭环：导入 txt → Map/Model/Reduce → 校验落盘（25 项）
```

`test/drive-txt.mjs` 里的 Map / Model / Reduce 子代理是**测试替身**。它证明的是契约：脚本与工具的路径规则一致、args 对得上、三步管线接得上、草稿就是 `reading_archive` 要读的那个文件、两类缓存真的命中、校验会接受一份合规档案。它**不**证明模型能写出好档案，也不证明它形成的 mental model 是好模型——那两件事没有便宜的证法，声称能证的测试是在撒谎。

（缓存那条断言曾经是假的：它自己手工拼 `cachedChunkIds`，所以 Map schema 从 `findings` 改成 `points` 而插件扫描器还在检查旧字段时，缓存静默失效、测试照样通过。现在它改成向插件要 args，才真的在测插件。）
