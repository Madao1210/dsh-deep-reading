# Map：精读一个块

你只负责这一个块，不要越界去讲整章。你的产出**不是一个摘要**，而是若干**讲得透的 point** 的原材料。

后面的合成步骤要靠你的产出写档案。档案里第一节只放作者明说的东西和逐字引文，第二节放推出来的机制与边界——所以你在这一步就要把（作者说的）和（你想出来的）分开，而且要**明确标出哪一个你没想出来**。

## 你读什么

- 书：%%TITLE%%
- 章节：%%CHAPTER_ID%%
- 你这一块：**%%CHUNK_ID%%**，原文第 %%START_LINE%% – %%END_LINE%% 行
- 原文文件：`%%SOURCE_PATH%%`

用 `read` 打开原文文件，**只读你这一段的行范围**（用 `offset` / `limit`）。不要读整本书：你多读的部分不会让你更准，只会让这一步更贵。

## 你怎么交付（重要）

**用 `write` 工具把结果 JSON 写到这个文件：**

```
%%MAP_OUT_PATH%%
```

内容是下面这个结构（只写 JSON，不要包代码块、不要加解释）：

```json
{
  "chunkId": "%%CHUNK_ID%%",
  "points": [
    {
      "claim": "作者的主张，用你自己的话转述",
      "evidence": "原文里支撑它的例子 / 数字 / 案例",
      "quote": "从原文逐字复制的连续文本",
      "mechanism": "为什么是这样。作者没明说但逻辑上成立的推导",
      "boundary": "什么情况下不成立；作者有没有承认这个边界",
      "missing": []
    }
  ],
  "openQuestions": ["作者提出但没回答的问题"],
  "gaps": ["这一段没有覆盖、但你预期会出现的内容"]
}
```

**你的最终答复就是同一个对象**（结构化输出会按给定结构校验）。写完文件后不必再复述内容，也不必贴文件正文——合成环节直接读这个文件。

## 一个 point 的四个槽位

每个 point 都要填四件事。这不是可选格式，这是这一步的全部要求：

1. `claim` —— **主张**：作者说了什么。用你自己的话转述，不要抄原文整段。
2. `evidence` —— **证据**：他拿什么支撑它。例子、数字、案例，具体到能复述。
3. `mechanism` —— **机制**：为什么必然是这样。激励在谁身上、约束是什么、哪一步是不得不。**作者常常只给结论不给推导，这一段就是你自己推的部分。**
4. `boundary` —— **边界**：什么情况下这条不成立。作者自己承认的例外写在这里；他用了限定词（（多数情况下）（只有在……才）（至少在这两个县））也要写在这里。

`quote`：**逐字引文**，从原文文件里原样复制一段连续文本（10–200 字为宜），支撑这个 point 的主张或证据。
插件会拿它和原文做逐字比对（去空白、去引号、忽略大小写后子串匹配）。**比对不上，这个 point 和依赖它的档案都会被拒收。** 不要凭记忆写引文，不要修标点，不要用省略号拼接两段不相邻的文字。

## 想不出来就标出来，不要硬编

- 推不出 `mechanism`：`mechanism` 留空字符串，并在 `missing` 里加 `"mechanism"`。
- 作者没给边界、你也看不出：`boundary` 留空字符串，并在 `missing` 里加 `"boundary"`。
- 这一段里只有主张、没有任何支撑材料：`evidence` 留空字符串，并在 `missing` 里加 `"evidence"`。

`missing` 只能取这三个值。**它是给下游看的信号，不是失败**：档案第二节会据此把（限制）写成（原文未给边界）。

反过来，**硬编是最严重的错误**：把你自己想出来的机制写进 `evidence`，或者编一条作者没说的边界，都会让档案变成一份看起来完整、实际上每一句都要读者重新核对的东西。

## 其他两个字段

- `openQuestions`：这一段里作者提出但没回答的问题、论证停住的地方。
- `gaps`：空白和内容一样是发现。你预期会出现但文里没有的东西，写在这里。

## 纪律

- **没有引文就不要写 point。** 宁可少写几条，也不要凭空概括。
- 不要评价作者对不对（那是读者的活），只如实提取。
- 不要写（本文主要讲了……）这类整体概括——你只看到了一段，概括必然是错的。
- 一个 point 只讲一件事。两件事硬并成一条，后面四步就都讲不清。
- 出现转折词、限定词（（但是）（不过）（只有在……才）（至少）（多数情况下））的句子**优先**收进 `boundary`：这类句子最容易在摘要式阅读里被丢掉，而它们常常正好限定了前面那个主张的适用范围。

## 你之后会发生什么（这决定了你该怎么写 point）

你的产出会被这样用：

```
你的 point  ──┐
              ├──→  MODEL：读完整章形成 mental model 与讲解顺序
其它块的 point ┘         │
                         └──→  REDUCE：把各点挂到 model 上，写出档案
```

两件事因此对你成立：

**一、你不负责判断整章在讲什么。** 那是后面 MODEL 步骤的事，它会**读整章**——比你看得多。所以：

- 不要写（本章的主旨是……）。
- 不要在 `claim` 里写跨块的概括。你只看到了一段，跨块概括必然是错的。
- 不要为了迁就一个自己猜的（本章主题）而筛掉不合主题的材料。

**二、你的 point 会被重排。** 讲解顺序由 MODEL 决定，可能是原序，也可能不是。所以：

- **每个 point 要自足**：不依赖（上一段说过什么）才能读懂。写 `claim` 时把必要的前提带上。
- **在 `boundary` 里写清这个 point 在论证里被用来干什么**——它是前提、是结论、还是对前一个主张的限定。重排的人要靠这个判断它该排在哪里。
- **不要用（如上所述）（接着上一段）这类指代**：重排之后它们全都指错地方。
