# Model：在讲之前，先把这一章想明白

你已经知道后面有人会拿你的产出写讲解。在你之前，另一个环节已经把本章按块精读过一遍，产出了一堆 point（主张/证据/机制/边界）。

**但那些是碎片。** 它们按原文顺序排列，带上分块边界。如果讲解直接从它们出发，讲出来的就是一节一节的原书注解——听的人会说（解释很聪明），然后补一句（可你还是带我精读）。

你要做的是这一轮里唯一一件需要**读完整章**的事：把这一章在自己脑子里重新组装一次。

## 你读什么

- 书：%%TITLE%%
- 章节：%%CHAPTER_ID%% %%CHAPTER_TITLE%%
- 整章范围：原文第 %%START_LINE%% – %%END_LINE%% 行
- 原文文件：`%%SOURCE_PATH%%`

用 `read` 读**整章**（`offset` = %%START_LINE%%，`limit` = 本章行数）。这一章可能比你习惯读的长，但这一步只有一次，而且它的价值全部来自（整体读过）。

不要跳过中段，不要只读首尾。你要回答的问题是关于整章的，只读一部分必然答错。

## 回答两个问题

### 一、这一章真正在解决什么问题

用**一段话**回答。这段话要能当作三句话读——如果你需要五句才能说清，说明你还没抓住它。

判据（写完自己核一遍）：

- 它回答的是（在解决什么问题），**不是（讲了什么）**。摘要说（本章讲了 A、B、C），模型说（本章在解决 X，A 和 B 是它的两个后果）。
- 它**不能靠章节标题推出来**。如果你写的东西读者看目录就能猜到，那还是摘要。
- 它应该让人听完之后，对本章每一个细节的位置都有一个预期。

### 二、如果不能按原文顺序讲，我会怎么让一个没读过的人最快懂

给出你**实际会选择**的讲解顺序（步骤标题，按先后排列），以及为什么这个顺序最快。

**这不是要求你重排。** 原书顺序在说明文里常常是论证的一部分——先给前提再给推论，重排会把论证链打断。很多章节的最优顺序就是原序。

它要求的是：你必须知道**自己为什么用这个顺序**。所以：

- 选原序 → 说明为什么原序本身就在一步步搭出这个模型（哪一步在搭哪一块）。
- 选重排 → 说明原序哪里挡路（哪一步会让没读过的人先撞上一个还没定义的概念、或先看到结论再看到前提）。

两种情况都要写 `reason`。**（原序就好）而不给理由，等于没问过这个问题。**

## 你怎么交付（重要）

**用 `write` 工具把结果 JSON 写到这个文件：**

```
%%MODEL_OUT_PATH%%
```

```json
{
  "chapterId": "%%CHAPTER_ID%%",
  "chapterModel": "一段话：这一章真正在解决什么问题",
  "teachingOrder": {
    "shape": "source",
    "steps": ["第一步讲什么", "第二步讲什么"],
    "reason": "为什么这个顺序最快让人懂"
  }
}
```

**你的最终答复就是同一个对象**（结构化输出会按给定结构校验）。写完文件后不必再复述内容。

## 纪律

- **不要把 `chapterModel` 写成章节摘要。** 最像样的失败是写出一段流利、正确、但纯粹复述内容的文字——它会被下游当成骨架用，于是整篇讲解还是原书形状的。
- **不要为了（有自己的结构）而硬造结构。** 模型是从原文读出来的，不是强加的。读完觉得（其实原序就是最优）是完全可以的答案，只要你能说出为什么。
- **不要在这一步评价作者对错**，也不要写你的补充观点。那是后面（档案第二节和讲解里的 AI 视角）的事。
- 这一段只读原文，不要去找前面环节的 point 文件。你要形成的是一手判断，不是对碎片的汇总。
