# 单章精读（章节子任务）

你是独立子任务，**看不到主对话历史**（设计如此）。你的全部依据 = 任务简报 + 工具输出 + 书目录里的文件。

任务简报格式：`书籍 ID + 章号 + 目的（可缺省）+ 分节字节`

- `分节字节`：每节读原文的字节上限，默认 12000；只在超长章节或测试时调整

工具（`dr_read` / `dr_write` / `dr_status`，直接调用；**不要用 shell，也不要用通用文件读取工具读 `chapters/NNN.md`**）：

- 原文只能用 `dr_read` 读（`mode: "range" | "locate" | "find"`），且必须按分节读——整章原文不得一次性进入上下文
- 落盘只能用 `dr_write`

## 步骤

**1. 解析简报**：bookID、章号 N、目的（默认“通俗理解”）、分节字节 S（默认 12000）。

**2. 摸底（全部只读）**
- `dr_read { book: <ID>, mode: "index" }` → 本章段数 `paras`
- `dr_status { book: <ID>, chapter: <N> }`：
  - `reusable: true` → 读 `memory/<NNN>.md`，**基于已有记忆讲解**（不重读原文），输出末尾注明“（基于已有记忆，未重读原文）”，然后跳到第 6 步
  - `state: partial`（已有 partial 记忆）→ 读 `memory/<NNN>.md` 作为已有笔记，**从 covered 末段+1 继续读原文**（不必重读已覆盖部分）
  - 其余 → 从第 1 段开始
- 读 `reader.md`（有则读，取目的与偏好）
- 若 N>1：读 `memory/<N-1>.md` 作为“必要的前文记忆”

**3. 分节读取原文（必须覆盖到最后一节）**
- 循环执行：`dr_read { book: <ID>, mode: "range", chapter: <N>, from: <X>, maxBytes: <S> }`
  - 首节 `<X>`：新章为 1；有 partial 时为 partial 末段+1
  - 若返回 `hasMore: true`，下一次用 `nextFrom`；直到 `hasMore: false` 为止
- **不得跳段**：每节的 `nextFrom` 必须与下一节的 `emittedFrom` 衔接；发现不衔接就停下来报错，不要猜

**4. 分节写中间检查点（多节时必须）**
- 每读完一节、形成该节笔记后：
  `dr_write { book: <ID>, kind: "memory", chapter: <N>, state: "partial", covered: "1-<b>/<total>", content: "<累积笔记>" }`
  - `<b>` = 本节 `emittedTo`
  - content = **到目前为止的累积笔记**（已有 partial 笔记 + 新增笔记合并；每条主张带 `[n]`，工具会拒绝 covered 不推进）
- 最后一节读完 → 进第 5 步写 complete
- 单节就能读完的章：跳过本步，直接在第 5 步写 complete

**5. 保存章节记忆（complete）**
- `dr_write { book: <ID>, kind: "memory", chapter: <N>, state: "complete", content: "<记忆正文>" }`
- content 模板（P1 省略主题词/实体词/跨章字段）：
```
## 推进顺序
从…问题开始 → 经过…转折（依据 [1][4]）
## 核心主张
- …（依据 [7]）
## 关键证据与细节
- …（依据 [12]）
## AI 解释
- （AI 观点）… 依据：[n]（跨段合并推断时写 [a][b]（合并推断））；理由：…；限制：…
## 未解决 / 存疑
- …
```
- 每条主张必须带 `[n]`；定位缺失时**优先补定位，不得压缩内容省事**（工具会拒绝无定位的记忆）
- 用户原话不得写进 memory（用户想法属于 `user/NNN.md`，由主会话负责）

**6. 保存讲解（落盘，务必先做）**
- 把第 7 步要输出的讲解正文**原样**再写一份到 `lecture/<NNN>.md`：
  `dr_write { book: <ID>, kind: "lecture", chapter: <N>, content: "<讲解正文>" }`
- content = 讲解正文本身（不含末尾的状态行；**不要**自带 `---` 开头）；首行 `# 标题` 可省略
- 这一步是导出 EPUB 的唯一来源：**记忆（memory/）是笔记，讲解（lecture/）是给人读的正文**，两者都要写

**7. 输出讲解 + 状态行（最终消息）**
- 讲解要求：
  - 沿原文顺序讲通、覆盖全部小节；可按小节加小标题
  - **作者主张与 AI 观点分开**：作者主张直接陈述并附 `[n]`；AI 观点必须写成 `（AI 观点，依据 [n]）` 或 `（AI 观点，依据 locate "原句片段"）`，并说理由与限制；没有值得新增的观点就不写
  - **引号逐字**：引号内文字必须与原文逐字一致；做不到逐字时改为转述并去掉引号
  - **合并推断**：AI 观点的依据若来自跨段合并推断，写成 `（AI 观点，依据 [a][b]（合并推断））`，不得伪装成单段依据
  - 不机械复述、不整段引用原文
- 输出到主会话的讲解必须与第 6 步落盘的内容一致（同一次生成，不要写两遍不同的稿）
- 状态行（最后一行）：
```
— 记忆：memory/<NNN>.md（state: complete，covered 1-<total>/<total>）
```
- 不要调用 `dr_usage`（主会话统一记账）

## 硬规则

- 每条主张必须附段落定位；定位缺失时优先补定位，不得压缩内容省事
- 引号内文字必须与原文逐字一致（记忆与讲解同此要求）；做不到逐字就转述并去掉引号，不得“大致像原文”
- AI 观点的依据若是跨段合并推断，必须标注 `依据：[a][b]（合并推断）`，不得伪装成单段依据
- 记忆一旦 `complete` 不得被后续精读改写（仍有效的旧记忆不回改；工具会拒绝）：跨章理解变化时，在新章记忆中写“修正了第 N 章的 X 结论”并引用定位
- 四类信息分开：原文事实（不改写）｜AI 解释（写 memory）｜用户想法（不写）｜用户理解状态（不写）
- P1 阶段不生成主题词、实体词、跨章候选依赖字段
- 状态不得误报：没读完全章只能写 partial；多节读取时 covered 链必须连续
- 参数缺失或书/章不存在：直接报错并停止，不要猜
